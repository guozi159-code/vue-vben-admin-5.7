# 配置双远程仓库与推送保护

## 基本信息

- 关联需求/问题：同步 Vben 官方更新，并避免误将内部代码推送至官方仓库
- 影响范围：Git 远程仓库配置、Lefthook `pre-push` 钩子

## 修改背景

当前项目基于 Vben 官方仓库进行二次开发，需要同时满足以下需求：

- 日常开发成果提交至公司内部仓库。
- Vben 官方仓库发布更新后，可以直接拉取并同步上游变更。
- 避免开发人员操作失误，将内部代码推送至 Vben 官方仓库。

## 修改内容

### 配置双远程仓库

为本地 Git 仓库配置两个 remote，并明确各自职责：

| Remote | 用途 |
| --- | --- |
| `origin` | 公司内部项目仓库，用于日常拉取和推送内部代码 |
| `upstream` | Vben 官方原始仓库，用于获取官方更新 |

上游仓库地址：

```text
https://github.com/vbenjs/vue-vben-admin.git
```

需要同步官方更新时，从 `upstream` 获取变更，再根据项目实际情况合并至当前开发分支。remote 配置保存在本地 `.git/config` 中，不会随 Git 提交共享；其他开发人员首次克隆项目后，需要按上述职责自行配置并通过 `git remote -v` 检查。

### 增加推送目标检查

新增 `scripts/check-push-remote.mjs`，并在 `lefthook.yml` 的 `pre-push` 阶段执行：

```yaml
pre-push:
  commands:
    restrict-remote:
      files: git ls-files lefthook.yml
      run: node ./scripts/check-push-remote.mjs "{1}" {files}
```

脚本读取 Lefthook 传入的目标 remote 名称，仅允许向 `origin` 推送。当目标不是 `origin`、目标为空或直接尝试向 `upstream` 推送时，脚本输出错误信息并以非零状态退出，从而中止本次推送。

## 涉及文件

- `.git/config`：本地 remote 配置，不纳入版本控制
- `scripts/check-push-remote.mjs`：校验推送目标，只允许 `origin`
- `lefthook.yml`：在 `pre-push` 阶段触发校验脚本

## 兼容性与风险

- 开发人员必须安装 Lefthook 钩子，推送保护才会在本地生效；项目通过 `prepare` 脚本执行 Lefthook 安装。
- 使用 `--no-verify` 可能绕过本地 Git Hook，因此服务端仍应配置分支保护和仓库权限，作为最终安全边界。
- 如果未来公司内部仓库的 remote 不再命名为 `origin`，需要同步修改校验脚本。
- 从 `upstream` 同步更新前，应先评估官方变更与当前定制代码的冲突及兼容性。

## 验证方式

1. 执行 `git remote -v`，确认同时存在 `origin` 和 `upstream`。
2. 执行 `node scripts/check-push-remote.mjs origin`，确认脚本正常退出。
3. 执行 `node scripts/check-push-remote.mjs upstream`，确认脚本输出拦截信息并以非零状态退出。
4. 执行一次指向非 `origin` remote 的测试推送，确认 Lefthook 在实际 `pre-push` 流程中阻止操作。

## 回滚方式

1. 从 `lefthook.yml` 中删除 `restrict-remote` 的 `pre-push` 配置。
2. 删除 `scripts/check-push-remote.mjs`。
3. 如不再需要同步官方更新，可在确认 remote 名称后执行 `git remote remove upstream`。
