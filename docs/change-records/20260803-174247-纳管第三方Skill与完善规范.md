## 修改背景

为项目添加 Skill。修改前 `skill-installer`、`pua`、`find-skills` 已安装到项目目录，但未更新外部 Skill 来源清单和锁文件，现有同步与校验命令无法管理这三个 Skill。

## 修改内容

### 纳管三个第三方 Skill

在 `.agents/external-skills.json` 中登记以下第三方 Skill 的 Git 仓库、分支和仓库内路径：

- `skill-installer`
- `pua`
- `find-skills`

通过 `pnpm skills:sync` 从各自上游同步当前版本，并在 `.agents/external-skills.lock.json` 中记录实际 Commit SHA 和内容哈希。

### 完善项目 Skill 管理规范

在 `AGENTS.md` 中明确：第三方 Skill 默认必须登记来源并生成锁文件；项目自行编写或明确采用手工同步、手工维护方式的 Skill 可以不登记；修改后必须通过 `pnpm skills:check` 校验。

### 调整修改时间记录规则

更新修改记录模板和项目规范，修改时间统一使用创建记录时的当前实际时间，无需再向用户询问或确认。

## 兼容性与风险

- 不影响应用运行时功能。
- 外部 Skill 使用上游 `main` 分支；后续执行同步可能引入上游更新，应在提交前审查 Git 差异。
- `pua` 原安装器生成的 `.openskills.json` 不属于上游 Skill 内容，改由项目来源清单和锁文件记录来源信息。

## 验证方式

1. 执行 `pnpm skills:check`，确认五个第三方 Skill 的来源声明、锁文件和本地内容一致。
2. 执行 `node --check scripts/sync-agent-skills.mjs`，确认同步脚本语法正确。
3. 校验来源清单与锁文件中的 Skill 集合一致。
4. 对三个新增 Skill 与对应 Git 上游目录进行完整内容比对，确认无差异。
5. 对项目自有修改执行暂存区空白字符检查，结果通过；外部 `skill-creator` 上游文件保留两处原始尾随空格，以维持内容哈希一致。
